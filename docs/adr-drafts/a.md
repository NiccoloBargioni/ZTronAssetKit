# WP-A decision drafts (Model: manifest decoding and validation, logging seam)

Stage 2, level L1, branch `wp/a`. One entry per non-trivial decision, in the `DECISIONS.md` shape (context · options · decision · consequences); the orchestrator numbers them at merge. Measurements were taken on this host (Apple silicon, macOS 27, Swift 6.4) in this session; "release" means `swift test -c release -Xswiftc -enable-testing`, "debug" the `--quick` configuration.

**Proposed REENTRANCY rows:** none. WP-A adds no `await` inside an actor (the only new `await`s are in tests).

**Contract changes requested:** none blocking. Five optional improvements are listed under A-11; A-11.1 (the second meaning of `payloadTooLarge`) needs an orchestrator decision either way.

---

## A-1 — A two-pass streaming manifest decoder instead of `JSONSerialization`/`JSONDecoder`
- **Context.** R-MAN-1/2/3 and P-3: decode untrusted bytes in both wire shapes, quarantine per entry, reject structurally, never trap, ≤ 1 s and ≤ 4× the payload at 32 MiB, ≤ 80 ms for the 3.3 MB reference. Foundation's decoders materialise every key and value (an `NSString`/`String` per token, a dictionary per object) before the schema is applied, impose their own nesting limits, and on the iOS 15 runtime are the Objective-C `JSONSerialization`; a 32 MiB payload of short strings or one huge unknown member costs several times the payload before validation starts.
- **Options.** (a) `JSONDecoder` with a lenient `Decodable`; (b) `JSONSerialization` plus a schema walk; (c) a hand-written reader that validates RFC 8259 JSON in UTF-8 and materialises only what the schema needs.
- **Decision.** (c): `JSONCursor` (bytes, strings with escapes and UTF-8 validation, numbers, literals, iterative `skipValue` with the depth checked before a container is entered), `ManifestParser` (schema), `ManifestRules` (per-entry rules shared with `violations(of:limits:)`), `ManifestFootprint` (A-8). Two passes over the same parser: a *survey* that validates and counts without materialising, then a *build* with exactly reserved buffers. Printable ASCII is scanned eight bytes at a time (SWAR, `loadUnaligned`), keys are matched by length and first byte, the identifier index is built once and handed to `ValidatedManifest` through an internal `init(decoded:positions:…)` (no public or package signature changed).
- **Consequences.** Release: the 3.28 MB / 10,000-entry reference decodes in p50 18.4 ms, max 18.8 ms over 15 runs (budget 80 ms); a dense 32 MiB / 100,000-entry manifest in 193 ms at worst (P-3-scaled limit 818 ms); random, truncated, deeply nested and unterminated payloads are rejected by the survey before any allocation (peak growth ≈ 10 KB at 32 MiB). Debug: the dense 32 MiB manifest takes about 2.9 s of CPU (two passes; unoptimised code is 11–15× slower), TSan more. No recursion anywhere, so no input can exhaust the stack whatever `maxNestingDepth` is set to.

## A-2 — Read-only byte views in production code
- **Context.** C1 forbids mutable pointers and caps unsafe escapes at 3 (0 used). Scanning `Data` through its subscript or copying it to `[UInt8]` costs time or a full payload copy (1× of the 4× budget).
- **Decision.** The decoder reads the payload through `Data.withUnsafeBytes` as an `UnsafeRawBufferPointer` that never escapes the call; the rules read a string's UTF-8 through `utf8.withContiguousStorageIfAvailable` (or a copy for bridged strings), and `AssetID.hash(into:)` feeds the same bytes to `Hasher.combine(bytes:)`. Under `.keepFirst` the survey pass also keeps the accepted identifiers as views of the payload (`SurveyedIdentifier`, A-8) in a set that lives only inside the survey, within the same `withUnsafeBytes` call. All are read-only views; no mutable pointer, no `unsafeBitCast`, nothing the unsafe gate matches (`UNSAFE escapes found=0`). Every read is preceded by an explicit bounds check, so malformed input throws instead of trapping.
- **Consequences.** The unsafe budget stays at 0 of 3. A reviewer who reads C1 as "no pointers at all" would ask for a `[UInt8]` copy; that costs 1× of the budget and about 30 % of the decode time.

## A-3 — Values are checked on the payload's bytes before they are materialised
- **Decision.** Every text rule (identifier, `fileExtension`, `remotePath`, tag length, checksum) runs on the payload's bytes (or the decoded bytes of an escaped string). A value over its field's length limit is never turned into a `String`: a 32 MiB identifier is quarantined as `identifierTooLong(bytes:)` with `QuarantinedEntry.identifier == nil` ("when one could be read" is read as "when it was within its limit"). Unknown members are validated and skipped without allocation. The quarantine records the first violation in field order (identifier, fileExtension, remotePath, localPathComponents, localFileName, byteSize, checksum, tags, policy); `violations(of:limits:)` returns all of them in the same order, from the same functions.

## A-4 — Hardening choices R-MAN-2 leaves open
- **Decision.**
  1. *Path components* are capped at 32 per entry (the index's per-record limit, store design §2.3), quarantined as `malformedField("localPathComponents")`. The cap is internal (`ManifestRules.maxPathComponents`): `ManifestLimits` is a contract type.
  2. *Repeated members.* A repeated known member inside an entry quarantines it as `malformedField(<name>)`; a repeated `schemaVersion` or `assets` makes the envelope `unexpectedShape`. Parsers disagree on which duplicate wins, so the decoder never guesses.
  3. *Duplicate identifiers* are checked among identifiers that pass the identifier rules. `.reject` (remote manifests) throws `duplicateIdentifier` at the second occurrence, quarantined occurrences included: a repeated identifier makes the manifest ambiguous. `.keepFirst` (the legacy `manifest.json`) keeps the first occurrence that can be kept: only an *accepted* identifier makes a later occurrence a duplicate, quarantined as `malformedField("identifier")` (`ManifestEntryViolation` has no duplicate case, A-11.2). So `[{a, "p.ng"}, {a, "png"}]` keeps the second entry and legacy migration adopts its file instead of downloading it again (fix round 1; it was "any valid occurrence", which kept nothing in that case and contradicted the option's doc).
  4. *Unknown `policy` values* quarantine the entry (`malformedField("policy")`): the value set is closed within `schemaVersion` 1, and a publisher that adds one bumps the version.
  5. *Encoding.* UTF-8 only (RFC 8259 §8.1), a leading BOM tolerated; invalid UTF-8, raw control characters in strings, lone or mismatched surrogate escapes are `undecodable(.notJSON)`.
  6. *Numbers.* `byteSize` accepts any JSON number whose exact decimal value is an integer, as the prior art's `JSONDecoder` did when it read `byteSize` into `Int` (R-MAN-1, fix round 1): `1234.0`, `1.234e3`, `1E3`, `12340e-1`; a non-zero fraction (`1.5`, `1e-1`) is `malformedField("byteSize")`. The value is computed from the digits (`JSONCursor.integralValue(of:)`, no floating point, linear in the number's length whatever the exponent) and saturates (`1e400` is `byteSizeOutOfRange(Int64.max)`). `schemaVersion` still needs integer syntax (`1.0` makes the envelope `unexpectedShape`): the envelope is new, so no published manifest spells it otherwise.
  7. *remotePath.* A colon in the first segment is a scheme (RFC 3986 §4.2); `//` after the optional scheme is an authority. The `..` check reads the path as an origin or the transport might (fix round 1): the path ends at the first `?` or `#` (so `a/..?x` and `..#frag` are parent segments); segments are separated by `/`, `\`, `%2F` and `%5C` (either case), so `a/..%2Fb`, `%2e%2e%2fsecret` and `a\..\b` are parent segments; a dot may be spelled `%2e`. `..foo`, `...`, `.`, `%41`, and `?`/`#` themselves stay allowed: no `RemotePathViolation` case fits a query or fragment, and the transport rejects them per fetch (TR1-10); A-11.5 proposes a case so they are quarantined with a diagnostic instead.
  8. *Control characters* are Unicode Cc: C0, DEL and C1 (U+0080–U+009F), for identifiers and remote paths; format characters (U+200B, U+202E) are allowed.
  9. *Envelope.* `schemaVersion` (integer ≥ 1) and `assets` (array) are both required; members may come in any order: `assets` before `schemaVersion` is validated, skipped and parsed after the version check, so an unsupported version is never interpreted.
  10. *Entry limit.* Every element of the assets array counts, quarantined ones included; the parse stops at the first element past the limit with `tooManyEntries(count: limit + 1, limit:)`.
  11. *Required members* are the prior art's four: `identifier`, `fileExtension`, `remotePath`, `localPathComponents`; optional members given as `null` are absent; a non-object element is `malformedField("entry")`, counted by the survey like any quarantine (A-8).
  12. *Path-like text is not validated here.* `localPathComponents` elements and `localFileName` have no content rule beyond being strings (32 components at most): `..`, `/`, `\`, NUL, control characters and empty strings are accepted, as the prior art accepted them. The new store never uses them (R-SEC-2: manifest text never becomes a store path component); only legacy migration (WP-C) derives source paths from them (`<legacy root>/<components>/<resolvedFileName>.<ext>`). **WP-C must validate them before building a legacy path**: reject an empty, `.` or `..` component, one containing `/`, `\` or a Cc character, or over 255 bytes, and check that the standardised result stays under the legacy root. A Model rule would quarantine entries the prior art served (R-MAN-1) without protecting anything the store reads (fix round 1, declined as a Model rule).

## A-5 — How R-MAN-3's bounds are measured, and in which configuration
- **Context.** R-MAN-3's 1 s is a property of the shipped (optimised) decoder. The unit tests run unoptimised (`--quick`) and, in `--full`, under TSan, where the same dense 32 MiB decode takes about 2.9 s and over 20 s respectively. This allocator keeps no high-water mark (`max_size_in_use` reads 0) and no public allocation hook exists.
- **Decision.** Time is the decoding thread's CPU time (`CLOCK_THREAD_CPUTIME_ID`, immune to other tests and processes). The heap is `malloc_zone_statistics` in-use bytes: exact before and after the call (the result alive), and a peak sampled by a second thread that polls at a 10 % duty cycle, spinning on its own CPU time (no sleep): back-to-back polls hold the zones' locks and starved the decoder (a first version took 8 minutes). The §11 test `R-MAN-3: seeded fuzz …` checks every outcome in every configuration; asserts ≤ 4× (peak and retained) for each of its 31 limit-scale cases except under TSan (whose allocator replaces malloc; detected by its runtime image); asserts ≤ 1 s when the target is built optimised, and in an unoptimised build asserts that time is linear (32 MiB ≤ 64× the CPU of 1 MiB; a quadratic path would be about 1,000×). The harness's release run proves the time bound through `P-3: the reference decode rate holds … at the 32 MiB payload limit …` (BenchModel.swift), whose threshold is P-3's budget scaled to 32 MiB (818 ms, stricter than 1 s), so no literal threshold enters the benchmark target. Since fix round 1 that benchmark also runs the allocation worst-case classes, which `verify.sh --perf` runs optimised: minimal entries of 16-byte strings (also under `.keepFirst`), 24-byte path components, 61 one-byte tags per entry, huge identifier, tag and checksum, and 100,000 entries sharing one identifier under `.keepFirst`. Under TSan the limit-scale cases shrink to 1 MiB.
- **Consequences.** Measured (debug, R-MAN-3 test, retained = peak unless noted): dense 32 MiB 1.54×; minimal entries of 16-byte strings 3.47×; 24-byte path components 3.03×; 32 MiB `localFileName` 1.0×; escaped 32 MiB `localFileName` 1.25× peak; every rejected class ≈ 10 KB. Release unit-test run (optimised branch): dense 32 MiB 0.20–0.24 s CPU. The base seed is printed (`ZTRON_MANIFEST_FUZZ_SEED` replays a run).

## A-6 — `AssetID` equality and hashing, same semantics, fewer calls
- **Decision.** Equality stays byte-wise: lengths first, then `String ==` as a fast reject (bytes equal ⇒ canonically equal, so "not canonically equal" proves "bytes differ"), then the byte comparison. Hashing feeds the UTF-8 count and the bytes in one `combine(bytes:)` from contiguous storage, or from a copy for bridged (UTF-16) strings, so both representations of the same bytes hash alike (tested). Indexing 95,000 identifiers dropped from 0.44 s to 0.06 s in debug.

## A-7 — The R-OBS-1 interval seam · **NEEDS-HUMAN-REVIEW** (public API addition, authorised by ARCHITECTURE §13.5 item 2)
- **Decision.** `LogIntervalName` (`plan`, `transfer`, `verify`, `commit`, `gc`, `eviction`); `LogRoute.interval(_:category:_:) -> LogInterval` begins a signpost on the sink's signposter (`OSSignposter.beginInterval` with a fresh `OSSignpostID`, one static name per case) and reports a `.began` `LogIntervalEvent` to the tap; `LogInterval.end()` ends both (end it exactly once, typically with `defer`; it may span awaits; `isSignposted` is `false` under `TapOnlyLogSink`). `LogTap` gains `recordInterval(_:)` with a default that records the event's rendered `.debug` line, `interval <name> <began|ended>[: <message>]`, which `LogIntervalEvent(line:)` parses back; existing taps (`RecordingLogTap`) therefore see intervals without a change. The tap is told even though the unified log receives a signpost rather than a line (ADR-047's "the tap sees what the unified log receives" holds in substance). Tests use `OSSignposter.disabled`, so nothing reaches the unified log.
- **Owners** (enforced by `R-OBS-1: every signpost interval has a call site once the work package that owns it has no stub left`): plan → WP-F (`ZTronAssetSync`), transfer → WP-D (`ZTronAssetTransport`), verify and commit → WP-B, gc and eviction → WP-C (`ZTronAssetStorage`). The test accepts a missing call site only while the owner's target still contains `fatalError("WP-<owner>` stubs, and prints the intervals still pending; today all six are. A call site is a `.interval(.<name>` in code. The orchestrator should confirm the transfer owner (WP-E's Apple transfers may wrap themselves too; any call site satisfies the rule).

## A-8 — An allocation budget checked before anything is built
- **Context.** Measured worst cases of a one-pass decoder: a payload made of 16-byte strings in path-component arrays reached 4.30× (three JSON bytes of punctuation per element against a 16-byte slot plus a 64-byte heap string), and 100,000 minimal entries of 16-byte strings 4.31× (growth copies of the entry array and the identifier index). R-MAN-3 says "never".
- **Decision.** The survey pass counts accepted and quarantined entries and every string and array the build pass will materialise; `ManifestFootprint` turns the counts into bytes with Swift's native 64-bit layouts (strings over 15 UTF-8 bytes: 32-byte header + bytes + NUL; arrays: 32-byte header + elements; dictionaries and sets: one power-of-two table ≤ ¾ full) and Apple's allocator blocks (`allocated(_:)`: 16-byte quanta up to 1,008 bytes, 512-byte quanta up to 15 KiB, 32 KiB steps above, the coarsest step any Apple platform uses for that size). If the estimate exceeds three times the payload (75 % of the bound; floor 64 KiB for tiny payloads), the manifest is rejected with `ManifestError.payloadTooLarge(bytes: estimate, limit: limit)` before any value is materialised; otherwise the build reserves exactly the counted capacities (no growth copy). What the survey counts (fix round 1):
  - *every* element of the assets array: an element that is not an object (`1`, `null`, `[]`, `""`) is a 48-byte `QuarantinedEntry` for two or three payload bytes. The survey used to skip them, so `[1,1,…]` × 100,000 (200,001 B) built 8.4 MB of diagnostics (41.9×) and grew the unreserved array; it is now rejected with about 10 KB of peak growth, like `{}` × 100,000.
  - under `.keepFirst`, the repeats of an accepted identifier, exactly: the survey keeps the accepted identifiers as views of the payload (`SurveyedIdentifier`, compared and hashed by their decoded bytes, no hash standing in for equality), so the build reserves `entries`/`positions` for the entries it keeps and `quarantined` for the repeats. It used to count repeats as accepted and leave the quarantine unreserved: 100,000 minimal entries sharing one identifier (8,100,001 B) peaked at 4.66× (4.27× in this session's test run); they now decode to 1 entry and 99,999 diagnostics at 0.63–0.73× peak. The survey's set is released when the survey returns (`ManifestParser.survey(_:options:)`), before the build allocates, so it is not in the estimate; the worst case for it, 100,000 distinct minimal entries of 16-byte strings under `.keepFirst`, measured 3.03× overall.
  - the identifiers of quarantined entries only under `.reject` (where the build remembers them), so a manifest of id-less diagnostics no longer pays for an identifier set.
  - per-entry arrays above the 16-byte-quantum class at their real block size: 64 one-byte tags are a 1,056-byte request served from a 1,536-byte block; the old model rounded to 1,072 and accepted such a manifest at an estimated 2.96× that measured 3.66× (3.54× here). It is now rejected; 61 tags (1,008 bytes, the largest tiny block) are accepted and measured 3.03×.
- **Consequences.** The 16-byte-component shape is rejected at about 10 KB of peak growth; 24-byte components (3.03×) and minimal 16-byte entries (3.47×) are accepted; realistic manifests estimate about 1.3× and measure about 1.5×. A legitimate manifest is rejected only if most of its bytes are 16–31-byte strings in arrays, which no catalog shape has. **Quarantine-dense manifests of tiny elements are rejected whole** (fix round 1, pinned by `R-MAN-3: quarantine diagnostics count against the allocation bound, so only a payload dense with tiny invalid elements is rejected whole`): a diagnostic costs 48 bytes, so a manifest whose elements are mostly `{}` or `1` needs 16–24× its payload in diagnostics; 1,000 × `{}` (3,001 B) fits the 64 KiB floor and is quarantined element by element, 20,000 × `{}` (60,001 B) is `payloadTooLarge`. R-MAN-2's per-entry quarantine therefore holds up to about one diagnostic per 16 payload bytes; realistic quarantines are far below (2,000 entries with 32-hex checksums, about 150 B each, are all quarantined, tested). Holding R-MAN-2 at any density needs a bounded diagnostic list (A-11.4). `payloadTooLarge` now has a second meaning, documented on the case; A-11.1 proposes a dedicated case.

## A-9 — Source scans that bind other work packages
- **Decision.** `R-ENV-1: no production source outside the live conformers calls …` defines a live conformer as a type whose name starts with `Live` or `System` (`LiveTimeSource`, `SystemRandomSource`, `LiveLoopbackDelay`, and the other WPs' `Live*` types), and scans for `Date()`, `Date.now`, `Date.init()`, `Date(timeIntervalSinceNow`, `Date.init(timeIntervalSinceNow`, `: Date = .now`, `DispatchTime.now(`, `DispatchWallTime.now(`, `: DispatchTime = .now(`, `deadline: .now(`, `wallDeadline: .now(`, `asyncAfter(`, `Timer.`, `Timer(`, `DispatchSource.makeTimerSource`, `Task.sleep`, `Thread.sleep`, `usleep(`, `nanosleep(`, `SystemRandomNumberGenerator`, `arc4random`, `UUID()`, `CFAbsoluteTimeGetCurrent`, `mach_absolute_time`, `clock_gettime`, `ContinuousClock`, `SuspendingClock`, `systemUptime` and `.random(` without `using:`; a pattern that starts with a name matches only where a name starts (`lastUpdateDate()`, `EngineTimer.` are not hits). `R-OBS-1: every log line uses subsystem com.ztron.assetkit …` allows `Logger(`/`OSSignposter(`/`OSLog(` only in `AssetLog.swift`, forbids `print(`, `debugPrint(`, `NSLog(`, `os_log(`, `dump(` in `Sources/`, `LogLine(subsystem:` outside `ZTronAssetModel/Environment/`, `LogCategory(rawValue:`, any interpolation in a `.log(`/`LogLine(`/`.interval(`/`.emit(` statement that names `id`, `ids`, `identifier(s)`, `assetID`, `rawValue`, `remotePath`, `url`, `URL`, `appKey` or `key` without `hashed(`, and (fix round 1) a log statement that uses a name which, earlier in the same function, was bound (`let`/`var`, `=` or `+=`) to text with such an unhashed interpolation. `R-MAN-7: no Model source performs I/O …` exempts only a bodiless `func` declaration (a protocol requirement naming a type), no longer every line containing `func ` (fix round 1). All scans lex Swift: comments and string contents are blanked, but the code inside an interpolation (`\(…)`, `\#(…)` in a raw string, nested strings included) stays code (fix round 1: it used to be blanked, so `"at \(Date())"` passed); each scan first proves itself on a known-bad snippet that includes these forms.
- **Consequences.** Later work packages must name their live conformers `Live…`/`System…`, schedule only through `TimeSource`, and log through `LogRoute` with hashed identifiers; a violation fails the scan with `path:line`. Known limits of a lexical scan: a `Date` reached through type inference in an argument (`f(at: .now)`), and a message passed across functions before it is logged, are not seen.

## A-11 — Optional contract improvements (not needed for WP-A's scope)
1. `ManifestError.decodedSizeExceeded(bytes: Int64, limit: Int64)` for A-8, instead of the second meaning of `payloadTooLarge` (where `bytes` is an estimated decoded size, not the payload size). **Orchestrator decision needed either way:** accept this case, or record the overload in `DECISIONS.md` and ARCHITECTURE §7.6 so WP-F (engine) and WP-G (diagnostics) map it on purpose; today only the doc comment on the case records it.
2. `ManifestEntryViolation.duplicateIdentifier` for `.keepFirst` duplicates (today `malformedField("identifier")`).
3. `ManifestLimits.maxPathComponents` (today an internal constant of 32, A-4.1).
4. A bounded quarantine: `ValidatedManifest.quarantinedCount` plus the first N diagnostics (for example 1,000), so R-MAN-2's per-entry quarantine holds at any density instead of rejecting a quarantine-dense manifest whole (A-8).
5. `RemotePathViolation.queryOrFragment`, so a `remotePath` with `?` or `#`, which the transport rejects on every fetch (TR1-10), is quarantined with a diagnostic instead (A-4.7).

## A-12 — Deliberately untested lines, and tests that touch the real world
`OSLogSink.write(_:)` and `AssetLog.logger(_:)` write to (or prepare) the unified log, which no test may touch (owner directive, ARCHITECTURE §14); they run only under `.live()`. `JSONCursor.scanString`'s opening-quote guard is an unreachable defensive line. That `LogInterval.end()` calls `endInterval` on the sink's signposter is not observable (`OSSignposter.disabled` gives no feedback): the tests assert `isSignposted` and both tap edges only. One test deliberately touches the live clock: `R-ENV-1: the live clock's readings never go backwards and a deadline already passed returns without sleeping` is the only coverage of `LiveTimeSource`; it reads the monotonic, awake and wall clocks (asserting order only for the first two, and for the wall clock only that it reads a date after 2023-11-14, which a time-server step cannot break) and enters `Task.sleep` through the live conformer for a deadline an hour away in a cancelled task, which returns at once; nothing waits on real time. Model coverage and the TSan run are in the fix-round report (A-13).
