## Benchmarks (release, this Mac)
- Statistics (B-9 as ruled): P-2 p95 of cold loads; P-5 p95 of both the ordered and the durable commit, commits-per-second a hard maximum; P-6 best of five; **P-13 the maximum deletion-unit duration** (SPEC §6: "in batches ≤ batch_ms_max ms between suspension points" bounds every batch).
- Orchestrator reference runs on the merged head (no other agent running; load average 1.9–2.6 for runs 2–3, ~5 for run 1):
  - P-2 p95 8.50 / 8.59 ms (budget 25); P-3 p50 16.6–17.9 ms (budget 80); P-5 ordered p95 13.2 / 13.3 ms, durable p95 32.0 / 29.0 ms (budget 40), ≤ 4 commits/s; P-6 2,546 MB/s, 0.815× one-shot, resident delta ≤ 0.016 MiB; P-10 8 connections (max 8).
  - **P-13 fails in all three runs:** total 0.58–0.63 s (budget 2.0 s), unit p50 0.96 ms, p95 0.99 ms, but unit **max 9.2 / 11.0 / 11.6 ms** (budget 5.0 ms). Every over-budget unit (2–3 of ~490) contains exactly one blob `unlink` that blocked in the kernel for 5.2–10.8 ms, against a volume profile of p50 0.04 ms and p99 0.055 ms; the unit's own on-CPU time is ≤ 1.02 ms (the injected per-unit time bound is 1 ms, B-10).
  - **Proposal to the owner — NEEDS-HUMAN-REVIEW (SPEC §6 "propose a new number"; `quality-gates.json` is not edited, the benchmark keeps asserting the maximum and fails until the owner rules):** a single APFS `unlink` occasionally stalls ~10 ms, so no unit size can bound the maximum below that. Option A (recommended): read P-13's per-batch bound as **p99** (as P-1 and P-9 already state their latency bounds); measured p99 ≈ 1 ms. Option B: keep the maximum and raise `batch_ms_max` to 15 ms. Either needs the owner's edit of SPEC §6 or `quality-gates.json`.

## Ratified decisions
- **WP-B:** B-3 index byte layout (**NEEDS-HUMAN-REVIEW**: on-disk format); B-10 time-bounded deletion units (ARCHITECTURE §4.4: units of at most 64 keys **and** at most `BlobDeletionUnit.budget` of the injected clock); B-12 adoption binds records to live blobs (§4.5); B-16 internal test seams that write WP-C fields (never public; WP-C may switch those tests to its real APIs); B-18, B-19; B-27 fan-out durability; B-28 with its amendments (commit-unit rules: ENOSPC fallback keeps the newest valid generation, step 5 rolls back step 4, a loaded `index.tmp` is promoted first, a lost-result rename is undone, the committed file is tracked by name, never inferred from a header); B-29 commit backoff; B-30 admit digest; B-31; B-32 and B-35 lifecycle; B-33 exhaustive state space, including amendment 3's narrower reading of I-a; **B-34** one read-only lifetime after an index stat/read error (the relaxation for an unreadable `index.prev` beside a valid `index.bin` is declined); B-36 nothing counted committed until a root sync ordered the names; B-37, B-38.
- **WP-D:** D-10 an explicit `shutdown()` cancels in-flight background downloads (the Model's drop-to-cancel rule) — **NEEDS-HUMAN-REVIEW**; D-19.1 a background 206 continues only a task created from resume data for checksummed content (others are `unexpectedStatus(206)`; device check pending); D-19.2 the "created from resume data" flag travels in the task tag across relaunch; the overflow saturation and size clamping of round 3 / cycle 1.
- **WP-E:** **Mutex exception** — `Synchronization.Mutex` is allowed only inside code gated `@available(iOS 26.0, macOS 26.0, *)` (the Apple-hosted tier), never `@unchecked`, with no await or I/O inside a critical section (types: `PackTransferStop`, `HashingChunkSource`, `FileHandleChunkReader`); amends ADR-003 and APPLE-API-VERIFICATION §4.7 (row 19, item 7). **ADR-027 applies literally:** a pack is released at most once per pack per catalog generation and is never re-armed within a generation (E-10(b) withdrawn); a pack downloaded again on demand after its release stays installed until a reclaim in a later catalog generation releases it. `sourceCopyBytes()` counts adopted packs, packs released in this process that came back, and (after the L2 follow-up) packs whose planned removal has not yet succeeded. E-10 released-pack tracking stays in memory (persisting needs a store field; deferred). E-1, E-4, E-13 (internal documented test seams allowed in production targets, never public), E-15 ratified. NetworkAccess: BackgroundAssets cannot honour `TransferRequest.access` / `ManifestRequest.access`; the Apple tier ignores it by necessity (E-17).
